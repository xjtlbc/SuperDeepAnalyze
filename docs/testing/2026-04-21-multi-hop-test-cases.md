# SuperDeepAnalyze - Agent 多跳推理能力测试用例

> **日期:** 2026-04-21
> **测试目标:** 验证 Agent 通过多次工具调用、信息串联、逻辑推理得出正确答案的能力
> **核心关注:** 多跳问题是否能被正确拆解、每跳信息是否能有效串联、最终答案是否正确

---

## 问题背景

用户实测发现：
- **测试问题:** "陈平安是裴钱的师父，请问裴钱的拳法主要是跟谁学的。"
- **实际表现:** Agent 在 10 轮后结束，给出的答案不正确
- **期望表现:** Agent 应能识别这是一个多跳问题：
  1. 第 1 跳：陈平安教了裴钱什么？
  2. 第 2 跳：裴钱的拳法/武道修行跟谁学的？（可能需要找陈平安之外的其他师父/引路人）
  3. 第 3 跳：交叉验证多份文档的信息
  4. 综合推理出正确答案

---

## 测试用例设计原则

1. **已知答案** — 测试问题的答案必须能从知识库中找到，便于验证
2. **多跳依赖** — 答案不能通过单次搜索直接得到，需要至少 2-3 次信息跳转
3. **干扰信息** — 知识库中存在相似但不相关的信息，测试 Agent 是否能正确筛选
4. **推理链条** — 测试 Agent 是否能建立正确的逻辑推理链

---

## 测试用例集

### TC-MH-01: 师徒关系多跳推理

**问题:** "陈平安是裴钱的师父，请问裴钱的拳法主要是跟谁学的。"

**预期推理链:**
1. 搜索"裴钱"→ 找到裴钱是陈平安的弟子/徒弟
2. 搜索"裴钱 拳法"或"裴钱 武道"→ 找到裴钱的拳法来源
3. 可能涉及：裴钱是否还有其他师父？陈平安的拳法又是谁教的？
4. 综合得出答案

**通过标准:**
- Agent 至少进行 2 次以上不同角度的搜索
- 最终答案正确或合理（基于文档内容）
- 不是在第 10 轮被强制终止后给出无关联答案

**失败模式:**
- 10 轮强制终止，答案与问题无关
- 只搜索了一次就给出答案，未进行多跳推理
- 重复搜索相同内容，陷入循环

---

### TC-MH-02: 人物关系链推理

**问题:** "崔东山和齐静春是什么关系？他们之间有什么关联事件？"

**预期推理链:**
1. 搜索"崔东山"→ 找到崔东山的基本信息
2. 搜索"齐静春"→ 找到齐静春的基本信息
3. 搜索两人关联/共同出现的事件
4. 梳理关系链

**通过标准:**
- 能识别两个人物并分别查询
- 能找到两人之间的关联
- 回答包含具体的关系描述和事件

---

### TC-MH-03: 事件因果推理

**问题:** "剑气长城为什么重要？它在整个故事中扮演什么角色？"

**预期推理链:**
1. 搜索"剑气长城"→ 找到基本描述
2. 搜索与剑气长城相关的关键事件
3. 搜索相关人物在剑气长城的活动
4. 综合归纳其战略/象征意义

**通过标准:**
- 不仅返回剑气长城的定义
- 能关联到具体事件和人物
- 回答有层次（战略地位、象征意义、关键事件）

---

### TC-MH-04: 时间线推理

**问题:** "陈平安第一次离开小镇是什么时候？离开前发生了什么？"

**预期推理链:**
1. 搜索"陈平安 离开"→ 找到离开的相关描述
2. 从时间线中定位该事件
3. 搜索离开前的关键事件
4. 按时间顺序整理

**通过标准:**
- 能定位到具体的时间节点
- 能关联到离开前的因果事件
- 时间顺序正确

---

### TC-MH-05: 跨文档交叉验证

**问题:** "关于陈平安的性格特点，不同文档中是如何描述的？"

**预期推理链:**
1. 搜索"陈平安 性格"
2. 搜索"陈平安"获取更多信息
3. 识别不同文档来源的描述
4. 汇总对比

**通过标准:**
- 引用了多个文档来源
- 区分了不同文档的描述
- 有交叉对比分析

---

### TC-MH-06: 实体属性推理

**问题:** "裴钱的本名是什么？她为什么改名？"

**预期推理链:**
1. 搜索"裴钱"基本信息
2. 搜索"裴钱 原名"或"裴钱 改名"
3. 找到改名原因

**通过标准:**
- 正确找到原名（如果有）
- 解释了改名原因
- 引用了具体文档来源

---

### TC-MH-07: 数量/程度推理

**问题:** "小说中提到了多少位山字境修士？他们分别是谁？"

**预期推理链:**
1. 搜索"山字境"
2. 统计提到的修士
3. 搜索每位修士的详细信息
4. 汇总名单

**通过标准:**
- 能正确识别山字境修士列表
- 数量基本准确
- 每位修士有简要介绍

---

### TC-MH-08: 否定/排除推理

**问题:** "陈平安有没有在剑气长城住过？如果没有，他在哪里住过？"

**预期推理链:**
1. 搜索"陈平安 剑气长城"
2. 如果没有明确提到居住，搜索"陈平安 住处"或"陈平安 居住"
3. 找到实际居住地
4. 给出否定 + 替代答案

**通过标准:**
- 能正确处理否定问题
- 给出替代信息
- 不是简单地返回"不知道"

---

### TC-MH-09: 对比推理

**问题:** "陈平安和崔东山在武道修行上有什么异同？"

**预期推理链:**
1. 搜索"陈平安 武道"
2. 搜索"崔东山 武道"
3. 对比两人的修行路径
4. 归纳异同

**通过标准:**
- 分别查询了两人的信息
- 有明确的对比分析
- 指出了具体的相同点和不同点

---

### TC-MH-10: 隐含信息推理

**问题:** "宁姚和陈平安的关系是如何发展的？从相识到在一起经历了哪些关键节点？"

**预期推理链:**
1. 搜索"宁姚 陈平安"
2. 找到初次相识的事件
3. 搜索关键发展节点
4. 按时间线整理关系发展

**通过标准:**
- 识别了关系发展的关键节点
- 按时间顺序排列
- 每个节点有具体事件描述

---

### TC-MH-11: 长链推理（3 跳以上）

**问题:** "陈平安的本命瓷是谁打碎的？打碎后发生了什么？这对陈平安的修行有什么影响？"

**预期推理链:**
1. 搜索"陈平安 本命瓷"→ 找到本命瓷相关信息
2. 搜索"本命瓷 打碎"→ 找到谁打碎的
3. 搜索打碎后的影响事件
4. 搜索对修行的具体影响
5. 综合回答

**通过标准:**
- 至少进行 3 次不同角度的搜索
- 正确回答了三个子问题
- 建立了因果链条

---

### TC-MH-12: 信息冲突处理

**问题:** "关于齐静春的死因，文档中是怎么描述的？有没有不同的说法？"

**预期推理链:**
1. 搜索"齐静春 死"
2. 搜索"齐静春 死因"
3. 检查不同文档中是否有矛盾描述
4. 如有冲突，进行标注

**通过标准:**
- 找到了主要描述
- 标注了是否存在冲突
- 如有冲突，说明了不同版本

## Agent 行为指标测试

除了答案正确性，还需验证 Agent 的行为质量：

### TC-BH-01: 推理轮次充足性

**目标:** 验证 Agent 不会过早终止

**方法:**
- 对上述每个多跳问题，记录实际推理轮次
- 检查是否在第 10 轮被强制终止

**通过标准:**
- 多跳问题推理轮次 >= 需要的跳数 + 1（验证轮）
- 不被 `_FORCE_ANSWER_THRESHOLD` 过早截断
- 答案质量与轮次正相关

### TC-BH-02: 工具调用多样性

**目标:** 验证 Agent 不会只用一种工具

**方法:**
- 统计每次回答使用的不同工具种类
- 检查是否有合理的工具切换

**通过标准:**
- 至少使用 2 种不同类型的工具（如 search_vector + read_l1 + read_l2）
- 工具切换有合理的目的性

### TC-BH-03: 循环检测有效性

**目标:** 验证循环检测不会误杀合理查询

**方法:**
- 观察 Agent 是否有"看起来不同但被误判为重复"的查询被跳过

**通过标准:**
- 相同查询只执行一次
- 不同参数（即使相似）的查询不会被误判为重复

### TC-BH-04: 信息饱和度判断

**目标:** 验证饱和度检测不会过早触发

**方法:**
- 观察当 Agent 进行精准查询（返回结果较短）时，是否被误判为"信息饱和"

**通过标准:**
- 精准查询（如查找某个人的名字）不被误判为饱和
- 只有真正穷尽信息时才触发饱和

### TC-BH-05: 最终答案质量

**目标:** 验证最终答案基于实际搜索结果

**方法:**
- 检查最终答案内容是否引用了搜索到的具体信息
- 答案是否与工具返回的内容一致

**通过标准:**
- 答案包含从工具结果中提取的具体事实
- 不出现工具结果中不存在的虚构信息
- 有文档来源引用

## 测试执行流程

### 前置条件

1. 后端运行在 `http://127.0.0.1:8000`
2. 前端运行在 `http://127.0.0.1:5173`

### 执行方式

#### 方式一：前端 E2E 测试（agent-browser）

```bash

agent-browser open "http://127.0.0.1:5173/"

# 2. 进入 jltest 知识库
# 点击知识库卡片 → 切换到对话 Tab

# 3. 发送测试问题
agent-browser fill "placeholder=输入问题..." "陈平安是裴钱的师父，请问裴钱的拳法主要是跟谁学的。"
agent-browser click "text=发送"

# 4. 等待 Agent 回复（可能需要 1-3 分钟）
agent-browser wait 60000
agent-browser screenshot

# 5. 展开 Agent Loop 详情，检查工具调用链
# 截图保存
```

## 已知问题与预期

### 当前代码的已知限制

1. **`_FORCE_ANSWER_THRESHOLD = 10`** — 10 轮强制终止，对于 3 跳以上问题可能不够
2. **强制回答时丢失搜索结果** — 只传入 `tool_calls_log` 的摘要（tool name + input），没有搜索结果内容
3. **信息饱和度阈值 200 字符** — 对于精准查询可能过早触发
4. **系统提示词较弱** — 对多跳问题的拆解指导不够具体

### 修改后的期望

1. 阈值可配置或提升至 15-20 轮
2. 强制回答时包含完整的工具搜索结果
3. 饱和度判断考虑查询类型（精准查询 vs 广泛搜索）
4. 系统提示词增加多跳推理的具体指导
